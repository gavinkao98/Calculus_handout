二、發現（依四級分）

① 真衝突／損壞（已實測重現）

① 損壞F1 · 正典 deck 過不了 render 閘：provenance.py 仍指向已搬走的 HTML

pipeline/provenance.py:82 解析 doc:frag-sec-* 錨時讀 handout/html/standalone/chapter<N>-print-standalone.html。該檔於 2026-08-10 佈局重構（22b60fc）移到 legacy/html_handout/standalone/。§3.1 storyboard 有 4 個 divider 的 scaffold.problem 用 doc:frag-sec-3-1，且 meta.otf_enforce: true → schema 閘 4 ERROR → make.py 印「aborting」。今天沒有人能在不加 --skip-schema 或關掉 enforce 的情況下重 render §3.1。

同一根因讓 _selftest_pedagogy.py::test_schema_integration 變紅（fixture 的 doc:frag-sec-3-1 解析失敗 → 多印一行 provenance WARN，撞到斷言）。

對照：subagent 提示 .claude/agents/pedagogy-firstlearner-audit.md 已在同一次重構改寫成「既有 deck 錨指歷史 standalone（legacy/…）」，但 code 沒跟——正是 T1 硬化想殺的「文檔與 code 漂移」，只是這次漂在 code 側。修法：一行路徑改 legacy，或改為「legacy HTML → 若無則 latex/src」雙來源；順手讓 fixture 不依賴真檔。

① 衝突F2 · 兩份 LOCKED 內容稿的講義來源已在 lock 後改動，且無機制會發現

§3.1／§3.2 內容稿與 storyboard 的權威來源皆為 legacy/html_handout/fragments/ch03/sec-3-{1,2}.html（lock 於 2026-06-28／29）。之後該兩檔各被改了三次（07-03 難度緩解、07-06 revise ch01-04、07-26 平實化 66 條），word-diff 變動約 100 行（§3.1）／80 行（§3.2）。08-09 起講義唯一源又換成 latex/src/ch03/chapter3.tex。

  • 影片 why_trig_is_different 單元的 source: 欄引用講義原句「So far every derivative has yielded to algebra … funnels down to a single limit」——這兩句在現行 HTML 與 .tex 都已不存在（lock 版有、現版無）。旁白仍照舊版講義寫。
  • 07-03 難度緩解在講義補上了和差化積的角和推導（註記原文：「identity was load-bearing three times but never derived」）。影片 difference_quotient_for_sine 場仍把該恆等式當已知（「Here it is」）。這是內容層的分歧：同一節，學生看影片與讀講義得到不同的處理深度。

為何是 ①：CONTENT_METHODOLOGY.md §8 明定「講義改動 → diff → 外科修改 → scoped NFA」，但這條規則沒被觸發，因為沒有任何 stamp 把內容稿綁到講義的某個版本（對照 T1 對 storyboard↔spoken.yml 做的 derived_from sha 章）。NFA／OF／six-lens 的 rubric 都寫「權威＝講義 fragment」，現在有兩個講義（legacy HTML 與 .tex）、文字不同——稽核結果取決於 agent 開哪一個檔。

① 衝突F3 · AMP 敘述放大稽核的錨（expansion:* 標記）在 LaTeX 源中不存在

AMPLIFICATION-RUBRIC.md 與 video-amplification-audit subagent 都以講義 HTML 註解 <!-- expansion:intuition|application … --> 為候選來源池（§3.1 fragment 有 17 個）。chapter3.tex 中 expansion 的命中數為 0（唯一一筆是英文單字）。README 已規定「新內容稿一律錨 .tex」——照做的第一個新 deck，這道閘就沒有輸入，會靜默變成空跑。

修法二選一（由你裁）：把 expansion:* 以 LaTeX 註解移植進 .tex（講義線的事），或宣告 AMP 對 tex-anchored deck 退役、改由內容稿的 learning_goal／kind: motivation 當錨。

② discoverability／文檔與工具缺口

② 缺口F4 · 21 個 selftest 沒有統一 runner；doctor 綠不代表產線綠

kickoff 自己記載「呼叫慣例是混的、無單一 cwd 能跑全部」（4 個要從 video/ 用 -m，1 個要從 repo root），當時用 scratchpad 的臨時 shell 腳本繞過，該腳本不在版控。08-10 重構若有一支 run_selftests.py 在 pre-commit 或 doctor 裡，F1 當場就會被抓到。doctor.py 只驗工具鏈（venv／LaTeX／ffmpeg），不跑任何閘，所以「✅ 影片完整 render→compose」與「正典 deck 中止」並存。

③ 結構F8 · 視覺閘審靜幀，結構上看不見動態；教學閘驗「存在」不驗「品質」

VISUAL-FRAME V1–V9／A1–A7 的被審物是「每場最滿一幀」；唯一時間維是 V7（reveal 是否對上 beat）。因此 F7 這類問題不可能被視覺閘報出——§3.1 視覺 blocking 歸零與你看片不滿並不矛盾。教學閘 PD2／PD3／PD4／OF2／SC1／SC2 皆為確定性存在檢查（有沒有 motive 欄、divider 有沒有 problem、步驤有沒有被 covers 蓋到）；gate-1 自有判斷只剩 PD1（一 beat 多動作）、OF1（超出源）、SC-honesty。rubric 自己也把「可以更有動機／更慢／更清楚」一律劃為 advisory。07-19 grilling 的診斷「閘驗存在、不驗品質」我逐條對過 rubric 後認為成立。

③ 結構F9 · 時間模型＝旁白長度；難步得不到額外停留

beat 的畫面長度嚴格等於該 beat 音檔長度（scene-level 則由 FA 回推）。沒有「靜默 beat」的作者文法——唯一的無旁白 beat 是連續 {show a}{show b} 造成的 0.45 s reveal-only beat，且被 sync guard 當 warning。結果：一個承重推導步驄在畫面停留的時間，恰等於把它唸出來的時間。REBUILD_STATUS 列「時間分配無人管」待驗證——從 code 看不需要再驗，這是定義使然。

③ 結構F10 · 課的骨架＝講義環境表的轉錄

§3「環境 → 教學單元」表把第一刀切在講義環境上（一個 definition 一單元、theorem＋proof 一或兩單元、每個 example 一單元…），再允許重排。six-lens L2／L6 進一步要求每個環境都有單元覆蓋、不得 silent drop。這保證了完整與忠實，也保證了課的形狀就是書的形狀；scaffold 的 motive／problem／flag 是事後貼在這個形狀上的補丁。07-19 你已押這個病灶，我同意，並補一點：這不是「忠實教義」本身的錯，而是忠實被套用在「結構」層而非「宣稱」層——每個數學宣稱 source-bound 是對的，每個環境都要有場是多的。

③ 結構F11 · 人是流程中的單點：停點多、每個都等你

一節從開稿到成片，設計上的 ⛳ 停點包括：six-lens 裁決、copyedit 採納、旁白 sign-off（lock）、storyboard 過目、hook code 過目、視覺 advisory 逐條裁、A/B 裁決（T9／T10）、看片標記、定水位、重設計授權範圖……每個 session 幾乎都以「等使用者發動」結束。對數學正確與忠實，這是對的；對設計品質的迭代，這是吞吐量的天花板——現在整條線停了 7 週，等的是一份 27 場的看片作業。

③ 結構F12 · 非決定性 TTS＋「滿意的 take 不重合成」＋講義持續演進 ＝ 影片永遠略落後講義

MiMo 每次合成是不同 take（±10%），scene-level 一場一 WAV，改一個字＝整場重合成＋重 NFA。講義線這三個月對 ch03 改了三輪。兩者相乘：任何「讓影片追上講義」的動作都是計費且不可局部的。這支持一個排程結論：講義某章完全定版之後才開該章影片——而 Ch1–8 現在正好都定版了，是影片線過去三個月從未有過的好起點。

三、意見與建議（依槓桿排序；每條都是我的判斷，由你裁決）

R1先修 F1，並補一支統一 selftest runner（半天內；不需計費）

這是唯一「今天就壞」的東西。路徑改 legacy 或雙來源，fixture 改不依賴真檔，21 個 selftest 用一支 runner 從任一 cwd 跑完，doctor 加 --smoke。這不是新功能，是把 kickoff P0-3 當時用 scratchpad 繞過的東西補進版控。

R2不要再等 27 場看片作業；用證據直接做「水位」決定

07-19 定的執行序是 ①看片標記 → ②定水位 → ③重做。我的看法：F7／F8／F9 已經從 code 層回答了①想問的問題——動畫問題不在哪幾場，在每一場。建議把①縮成三場（一場 derivation、一場 theorem_proof、一場 graph hook）或直接跳到②。②的三個選項裡，「現系統內打磨」在 F7 之下無法解決「動畫死板」，因為系統內沒有動畫可打磨；剩下的真正分岔是「每節少數招牌場」vs「模板層普遍有動」。我偏向後者（見 R4），理由是成本結構。

R3把講義版本綁進內容稿，並把影片線真正收到 LaTeX 上

  • 內容稿標頭加 source_rev:（該節 .tex 文字的 LF 正規化 sha，或 git blob）；derive／schema preflight 比對 HEAD，不符即 WARN「講義已變、需走 §8」。這是 T1 的同一招，往上搬一層。
  • 給 .tex 一套錨文法（\label 已由 P2 編號語意化落地，可直接用 doc:thm:3.1／doc:sec:3.1 這類 label），provenance 解析器讀 \label{}；legacy HTML 錨只保留給既有兩個 deck。
  • AMP：裁 F3 的二選一。
  • §3.1／§3.2 既有稿：對 07-03 補推導那一處做一次 §8 的 diff→外科修改（這正好是重做試點會重寫的單元，可併入）。

R4動畫：加 3–4 個模板層 motion primitive，而不是更多 per-scene hook

hook 是成本驅動者（每個 80k–216k tokens、每節數個）且目前只產出「出現」。我建議在 blocks.py／模板層加少量可由 storyboard 宣告的原語，讓多數場不寫 hook 就有動：

  • derivation：step N → N+1 用 TransformMatchingTex（讓「這一步從上一步變出來」看得見），前一步自動退為 muted（A7 的 focus 目前只存在於靜態配色）。
  • theorem_proof：qed 時 statement 卡回閃一次（closure），而不是只多出一個綠點。
  • graph：ValueTracker 驅動的點沿曲線移動／切線掃過（plots[].sweep: {from,to}），這是 §5 願景裡最常被點名、也最能承載教學點的一種。
  • 通用：{hide X}／{focus X} 標記，讓場能「演化」而非只「累加」。

這些都在 reveal 模型內：每個原語回傳耗時，play_block 已支援 callable anim 並扣除 hold。風險在 sizecheck（建 scene 不 render）對動態終態的覆蓋，需要為每個原語定義「最滿幀」。

R5時間模型：加一個靜默 beat 文法

{pause 1.5} 或 {dwell}——parser 已按標記切 beat；manifest 已有 narration_mode: silent（場級），下放到 beat 級即可；FA 不受影響（靜默 beat 不進 transcript）。這是 F9 的直接解法，成本極低，對「難步停留」的教學槓桿高。

R6Stage-1 重設計：把第一刀從「環境表」換成「課的弧線」

試點的「重設計授權」我建議明講為：先寫一頁lesson arc（引導問題 → 探索／直覺 → 形式化 → 鞏固／回顧，每段列它要回答的問題），再把講義環境對映進去；對映不到的環境不強迫成場，改為「就近註明刻意併入或略過」。L1／L5 原樣保留（每個數學宣稱仍 source-bound）；L2／L6 的「每個環境都有單元」改為「每個承重想法都有單元」。這維持你 07-19 的邊界（無習題外洩、不加新數學），只換切法。

R7吞吐量：定義兩個製作等級，否則 30+ 節到不了

比照 07-07 gate-2 頻率矩陣的思路，把製作本身也分級：「標準節」＝模板＋R4 原語、零或一個 hook、gate-1 全跑、VLM 抽樣；「招牌節」＝現在 §3.1 的全套。每章挑 1–2 節做招牌。成本表要記兩行，才有資料決定招牌比例。

R8停點瘦身：你只親裁「數學／忠實」與「成片」，其餘交 gate-1＋VLM 收斂

保留旁白 sign-off（lock）與最終看片兩個人工閘；storyboard／hook／視覉 advisory 的迭代讓 gate-1 subagent 與 critic 在「blocking==0 且 A 分不降」下自行收斂，回報你一張 contact sheet（每場最滿幀＋一段 30 秒 motion 抽樣）而非逐項裁決。這是流程意見，與你偏好謹慎的取捨有張力，所以列在最後、明標由你定。

順序建議：R1（修壞的）→ R2（做決定）→ R3（把源鎖住）→ R4＋R5（工程，可離線、零計費）→ R6（試點重做，走新 mandate）→ R7／R8（量產前）。R1 與 R3 的第一小點各是一個下午；R4／R5 約一到兩週離線工作；R6 就是原本的 §3.1 重做試點，只是先有了 R4／R5 的底。
